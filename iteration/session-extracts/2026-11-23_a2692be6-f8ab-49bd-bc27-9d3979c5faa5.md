F. 主机 BLE 协议事实

`BleManager.java`：

```text
Service: 0000a002-0000-1000-8000-00805f9b34fb
Notify : 0000c305-0000-1000-8000-00805f9b34fb
Write  : 0000c304-0000-1000-8000-00805f9b34fb
CCCD   : 00002902-0000-1000-8000-00805f9b34fb
```

- 请求 MTU 517，不代表对端接受。
- 控制优先、`cmd+zone` 去重、串行写，优先 WriteWithResponse。
- GATT 写回执约 900 ms；普通业务回包约 2500 ms；控制提示超时约 5000 ms。
- 业务结果不明时不盲目自动重发用户控制。
- 舱位仅为 `left/right`；`enable` 为字符串 `"on"/"off"`。

主要命令：

```json
{"cmd":"get_all_status","zone":"left|right"}
{"cmd":"get_temp"}
{"cmd":"get_o2","zone":"left|right"}
{"cmd":"get_humidity","zone":"left|right"}
{"cmd":"get_co2","zone":"left|right"}
{"cmd":"set_temp","value":123}
{"cmd":"set_o2","value":225,"zone":"left"}
{"cmd":"set_co2","value":800,"zone":"left"}
{"cmd":"set_co2_enable","zone":"left","enable":"on"}
```

- `set_o2` 的 `value` 为界面百分比 ×10。
- `set_temp` 无 zone。
- 冷/暖光、红外、蓝光、内循环、雾化、负离子、紫外命令带 zone。
- `set_outer_cycle` 无 zone。
- `set_o2_enable` 有管理器实现，但普通 UI 和护理模式未接线。
- 五个定时命令：
  - `set_red_time`
  - `set_blue_time`
  - `set_nebulizer_time`
  - `set_anion_time`
  - `set_uv_time`
  - 均带 zone 和分钟 `value`。
- 定时开启顺序：时长 → 开关 → 600 ms 后补时长；时长入队失败则不开启。
- `65535` 是未单独设置时长的兼容哨兵。
- `get_run_time/set_run_time` 有实现，当前治疗时长 UI 只读。
- `set_status_light` 使用 `red/yellow/green`。
- 护理模式 outbound 值只允许：

```text
maternal_and_infant_care
Postoperative_care
Cardiopulmonary_care
Custom_mode
```

- `no_set_mode` 仅是主机回报状态，不是 App 第五个 outbound 模式。
- 护理模式互斥主要是 App 本地互斥，不是向主机发送三条“关闭其他模式”。

G. AM4100、红外、摄像、打印事实

AM4100：

```text
Service: 49535343-FE7D-4AE5-8FA9-9FAFD205E455
Notify : 49535343-1E4D-4BD9-BA61-23C647249616
Write  : 49535343-8841-43F4-A8D4-ECBE34729BB3
```

- 帧：`55 AA LEN TYPE PAYLOAD... CHECKSUM`
- `checksum=(~(LEN+TYPE+sum(PAYLOAD)))&0xFF`
- 类型：
  - `01` ECG
  - `02` HR/RESP
  - `03` NIBP
  - `04` SpO2/PR
  - `05` 温度
  - `06` 状态
  - `FE` 血氧容积波
  - `FF` 呼吸波
- NIBP 状态 0 或 7 采用。
- 独立 BPM 血压计接入不存在；血压来自 AM4100 `0x03`。
- 异常 GATT 断开和主动 close 的清值路径不同，不能笼统写“所有断连立即清所有标量”。

红外桥：

- 16 字节头以 `TH` 开始，含 version、frameId、packetIndex/count、payloadLength、width/height、timestamp。
- 像素为小端 signed int16，摄氏百度值。
- 支持乱序分片，重复序号只保留第一份。
- 完整帧后实际为读取 ACK 特征。
- 未见热图 checksum、生理范围检查、时间戳新鲜度检查或半帧组帧超时。
- timestamp 单位/epoch 待桥端协议确认。

摄像头：

- 仅 `rtsp://`，RTP/AVP/TCP interleaved，H.264。
- Basic/Digest，Basic/Digest 均不提供传输加密；无 RTSPS/TLS。
- H.265 明确拒绝。
- 未实现 UDP RTP、PAUSE、TEARDOWN、RTSP 保活或厂家云台控制。
- 截图可能回退缓存最后帧，不保证是当前实时帧。
- JPEG 最多 60 张，下载到 `Pictures/ICUCamera`。
- 录像到 `Movies/ICUCamera`，从关键帧开始，直接封装 H.264 MP4，无音轨。
- 完整含凭据 RTSP URL 保存在本机 SharedPreferences，文档需标安全风险。
- 对讲、遮蔽、翻转、巡航等未开放。

打印：

- auto 尝试 IPP、RAW 9100、LPD 515。
- 支持 PDF/JPEG/PWG/PCLm/URF/PCL 等路径。
- 配置地址时直连；无地址走系统打印；无系统打印服务可回退下载 PDF。
- 默认地址 `10.2.34.201` 是当前硬编码，不是通用现场地址。
- 份数 1–5，且只核对第一份。
- IPP 完整 flush 后读响应失败属于结果不明，不换协议盲目重发。
- RAW/PCL 某些 IOException 路径可重连重发整份任务，需测试重复打印。
- 多页部分成功后不能简单换格式重发。
- mDNS/主动 `/24` 端口扫描只能在明确授权网络执行。
- 即使解析 `ipps://`/`https://` 前缀，底层仍是普通 Socket/HTTP，不声称 TLS。
- IPP 受理、队列下降、系统 PrintJob 完成均不等于物理出纸。

65535 精确行为：

- 65535 原样存入主机回读缓存。
- 显示时映射为常量 99 分钟。
- 普通入库分钟仅接受 1..1440；0、负数、>1440 被 `applyTimedMinutes` 丢弃。
- 65535 或大于设定值的回读不能确认主机采纳了普通设定。
- 这是本项目事实，与旧项目“不要转 99”的记忆不同。

回包与超时：

- 成功优先 `ret`，缺省 `result`。
- 接受 Boolean true、数字 `intValue==0`、字符串 `ok/success/true/yes/0`。
- 裸 `ok` 无 cmd/data 时可按等待队头归属，但不能当完整状态。
- 开关只有 `ret:ok` 时仅 acknowledged，真实状态仍需总表。
- `set_care_mode` 可用等待项保存的实际 value 关联，不拿最新 pending 猜测。
- GATT 写回执约 900 ms。
- 普通查询等待约 2500 ms。
- 控制应用层超时 5000 ms。
- 控制等待项为识别迟到回包保留 10000 ms。
- 单舱无有效状态 10 秒、全局 20 秒。
- 写回执超时不物理重发，300 ms 后恢复队列。

队列：

- 去重键为 `cmd + ":" + 原始 payload zone`。
- 无 zone 的 `set_temp` 在待排队阶段共享 `set_temp:` 键。
- 控制优先但控制项之间 FIFO，不抢占正在写入的一条。
- 800 ms 左右舱轮换，正常单舱约 1.6 秒。
- 队列含 currentWrite 达到 8 条时跳过状态/护理轮询。
