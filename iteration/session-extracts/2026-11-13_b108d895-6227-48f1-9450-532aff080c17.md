2. Key Technical Concepts:

   - AM4100 实时标量、实时波形窗口、会话波形留档、趋势数组、带时间戳的测量历史是不同数据层。

   - “用于显示的最后值”与“允许报警的新帧值”必须分离。
   - `lastValidAtMs[7]` 与 `lastReadyAtMs` 可用于判断某参数是否在本次链路 ready 后重新上报。
   - `vitalsState()` 是 120ms 轻量数值桥；`waveState()` 包含波形和趋势大 JSON；`monitorHistory` 是另一套历史趋势桥，不能混为一谈。
   - `MonitorSnapshot` 按账号、舱位和稳定 `petId` 持久化，报告必须读取对应病例快照。

   - 被动状态提醒应按事件去重；按钮主动提醒不做全局去重。

   - AM4100 实时标量、实时波形窗口、会话波形留档、趋势数组、带时间戳测量历史是不同数据层。
   - `connected` 和 `protocolReady` 表示真实链路状态；最后有效显示值可以跨同设备断连保留。
   - “显示用最后值”与“允许报警的新帧值”必须分离。
   - `lastValidAtMs[7]` 与 `lastReadyAtMs` 可用于要求某参数在本次 ready 后收到新有效帧才恢复报警。
   - `vitalsState()` 是 120ms 轻量数值桥；`waveState()` 含波形与趋势；`monitorHistory()` 是另一套历史桥。
   - `MonitorSnapshot` 按账号、舱位和稳定 `petId` 持久化；报告只读对应病例快照。
   - 当前有效 PDF 模板使用 `sessionEcgWaveSamples/sessionSpo2WaveSamples/sessionRespWaveSamples`，不是旧版实时优先报告路径。
   - 长会话波形需要全窗口峰谷抽稀，不能只截取尾段；ECG 尖峰尤其需要保留最小/最大极值及原始先后顺序。
   - 历史测量全局容量固定且每帧追加，可能让高频参数挤掉其他参数；这是已确认的结构风险，但尚不是用户设备故障的唯一已证实根因。
   - 历史时间戳和数值必须真实，缺失/非有限值不能转成 0。
   - 被动报警按“参数＋超限方向”识别事件；持续超限不重复，恢复后再超限或高限转低限属于新事件。
   - BLE 断连弹窗应区分“尚未恢复的事件集合”和“当前弹窗正在展示的事件集合”，避免已确认旧事件随新断连再次出现。
   - 教程权限弹窗的 dismissed 状态只能抑制被动轮询重弹，不能禁止用户主动点击产生的权限反馈。
   - Debug APK 的构建、签名和资产核验不等于真实硬件功能验收。

2. Key Technical Concepts:

   - AM4100 实时标量、实时波形、会话波形留档、趋势数组和带时间戳测量历史是不同数据层。
   - `connected` 与 `protocolReady` 表示真实链路；最后有效值可以跨同设备断连保留。
   - `lastReadyAtMs`、`lastValidAtMs[7]` 用于逐项判断新帧新鲜度，防止保留旧值重新报警。
   - `MeasurementHistoryBuffer` 使用固定容量、按参数公平淘汰和重复点节流，避免某一高频参数挤掉其他参数。
   - `MonitorHistoryJson` 是 `monitorHistory` 原生桥的唯一序列化出口。
   - PDF 波形使用全窗口 min/max 抽稀，保留每桶峰谷及其原始先后顺序。
   - 被动报警按“参数＋超限方向”识别事件；无效帧不算恢复，真实恢复或高低限换向才形成新事件。
   - BLE 弹窗分别记录未恢复、正在展示和已经确认的链路事件。
   - 教程权限 dismissed 状态只抑制被动轮询重弹，不全局屏蔽主动反馈。
   - 主机 BLE 使用 JSON 文本协议：
     - C304 为 Write；
     - C305 为 Notify；
     - Notify 分片按大括号配平拼成完整 JSON。
   - 主机配置时长和实际剩余时长分开：
     - `redTime/blueTime/nebulizerTime/anionTime/uvTime` 保存用户配置；
     - `switchRemainingMinutes` 保存主机回报的剩余分钟。
   - 带定时开关先发送 `set_*_time`，再发送 `set_*_enable`，避免主机按旧时长启动。
   - `getControlTimeValue()` 返回配置分钟；`getControlDurationText()` 优先显示主机剩余分钟，缺失时才回退配置值。
   - `set_run_time` 和治疗累计时长是另一条路径，不应与五项功能定时混淆。
   - 控制回执、App 入队、GATT 写成功和主机物理执行不是同一件事。

     - C304 Write；
     - C305 Notify；
     - Notify 分片按大括号配平拼成完整 JSON。
   - 带定时开关先发送 `set_*_time`，再发送 `set_*_enable`。
   - 用户配置时长与主机实际剩余时长是不同语义：
     - `redTime/blueTime/nebulizerTime/anionTime/uvTime` 保存配置；
     - `switchRemainingMinutes` 保存主机回报剩余分钟。
   - `readRemainMinutes()` 通过 `normalizePresetMinutes()` 接受 1～1440 分钟；0、负数及大于 1440 的值返回 null。
   - `getControlDurationText()` 原本已经优先使用剩余分钟，但 H5 使用的 `getControlValue()` 原来只读取本地配置，造成两条显示链路语义不一致。
   - H5 `therapyDisplayText()` 原来对无数字的“开”使用 `DEFAULT_THERAPY_MINUTES=99`，这是“直接打开最大值”的界面来源。
   - 剩余时间缓存现在按 `currentZone + "|" + switchKey` 隔离，避免双舱串值。
   - 新时长入队后，对应旧剩余缓存失效，回读前回退到新配置值。
   - 治疗记录单三波形使用不同数据源：
     - ECG：`sessionEcgWaveSamples`，回退 `heartRateHistory`；
     - 脉搏波：`sessionSpo2WaveSamples`，回退 `spo2History`；
     - 呼吸：`sessionRespWaveSamples`，回退 `respHistory`。
   - `waveHasSignal()` 要求至少 6 个样本且 `max-min>2`，否则视为没有有效连续波形。
   - “趋势 14 点”是趋势采样点数量，不是 14 秒，也不是 14 个原始波形采样点。
   - AM4100 实时标量、实时波形、会话波形留档、带时间戳测量历史和趋势数组仍是不同数据层。
   - 控制回执、App 入队、GATT 写成功和主机物理执行不是同一状态。
